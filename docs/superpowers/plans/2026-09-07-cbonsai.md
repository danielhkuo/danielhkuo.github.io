# cbonsai implementation plan

Spec: `docs/superpowers/specs/2026-09-07-cbonsai-design.md`

Each step is one commit. Pure modules land with their `node:test` files.
All engine files use explicit `.ts` import specifiers so Node can run them
without a bundler.

1. **Reference build.** Compile `cbonsai.c` on macOS with a glibc `random()`
   shim substituted for `rand`/`srand`, run it under a pty at fixed
   `LINES`/`COLUMNS` with `-p`, and parse the ANSI output into cells. This
   produces the golden fixtures the port is compared against.
2. **`rand.ts`.** glibc TYPE_3 generator. Test against the known `srand(1)`
   sequence and the shim.
3. **`wcwidth.ts`, `screen.ts`.** Cell grid with dirty rows, wide-char
   continuation cells, ncurses-style `Win` with wrapping writes and clipping,
   a mask rectangle for the message panel, `snapshot()` to `CellRun[][]`.
4. **`args.ts`.** getopt_long port with cbonsai's optstring and long table;
   returns `{ kind: "run", config } | { kind: "help" } | { kind: "error", lines }`.
5. **`bonsai.ts`.** `drawBase`, `setDeltas`, `chooseString`, `chooseColor`,
   `branch`/`growTree` as generators yielding once per drawn step,
   `drawMessage`. Golden tests: several seeds × sizes × bases × messages ×
   leaves against the reference binary.
6. **`program.ts`.** `CbonsaiProgram`: live loop, infinite wait, key
   handling, save/load in `localStorage`, `-p` snapshot on exit.
7. **Terminal integration.** `types.ts` additions, `ScreenView.tsx`,
   `Terminal.tsx` program state and key forwarding, `commands.ts` lazy
   `cbonsai` command, `--ansi-*` palette and `.term-screen` CSS.
8. **Performance.** `scripts/bench-cbonsai.mjs` (Node) and an in-browser
   frame-time sample of `cbonsai -li -t 0.001`; record results in the
   commit message and the final report. Confirm first-load JS unchanged.
9. **Verify.** `npm run lint`, `npx tsc --noEmit`, `npm test`, `npm run
   build`, manual run in the dev server in both themes and on the mobile
   preset.
